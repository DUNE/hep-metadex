# Glossary: Technical Terms

| Term | Definition | Use When | Avoid |
| --- | --- | --- | --- |
| OpenSpec Store | A standalone OpenSpec repository, registered per machine, whose specs and changes are shared by multiple code repositories — see the [Stores documentation](https://openspec.dev/docs/stores). | Referring to hep-metadex in its store role, or to the OpenSpec Stores feature. | Using bare "store" in prose where a data store or persistence layer could be meant — this project's domain is metadata storage. |
| Store reference | A read-only declaration in a project's `openspec/config.yaml` (`references:` block) that injects an OpenSpec Store's spec index into artifact workflows. | Describing how an experiment repository connects to the OpenSpec Store. | Confusing with the write-routing `store:` config line, citation references, or calibration reference data. |
| Workflow scaffolding | The replicable workflow kit installed into each experiment repository: schema, skills, commands, subagents, agent guidance files, and — for GitHub-hosted repositories — the spec-validation workflow ([ADR-0005](../adr/0005-distribute-spec-validation-ci-as-host-conditional-scaffolding.md)). | Referring to what flows by template install rather than through the OpenSpec Store. | Using for code-generation scaffolding, or for specs and changes, which flow through the OpenSpec Store. |
| Spec index | The list of an OpenSpec Store's common capability specs — one-line summaries plus fetch commands — injected into the artifact workflows of connected repositories. | Describing what a store reference injects at change time. | Using for spec listings produced by other tooling. |
| Maintainer toolchain | The Python + uv tooling (interpreter pin, project file, dev dependencies) used to maintain hep-metadex itself. | Referring to how this repository's own tooling is built and run. | Confusing with the Workflow scaffolding, which flows out to experiment repositories, or implying an adopter mandate. |
| Documentation site | The Zensical-built static site published to GitHub Pages from `docs/` in place, built by `tools/docs_site.py` with out-of-tree links rewritten to GitHub URLs. | Referring to the published hep-metadex site that evaluators and adopter maintainers read. | Confusing with `docs/` (the source pages) or the README (the repository front door), or implying the site tooling reaches adopters — it is repo-local. |
