## Why

With #34 (add-versioned-kit-releases) archived, a merge that bumps the **Kit version file** cuts a **Kit release** automatically, and the bump-in-the-same-change rule carries the release discipline. But the rule itself relies on convention: the release workflow's own gates — changelog section, CLI pin, tag-exists — fire only after a bump, so a change that alters kit files and forgets the bump is silent at review time, and a change could otherwise complete its lifecycle with kit changes that no published release contains. Exploration on 2026-11-12 chose reminder-plus-archive-gate over reminder-only and over merge-blocking required checks: an advisory reminder catches the miss where it is cheapest, at review time, and a hard archive-phase gate backstops it — complementing the release workflow's existing post-bump gates — per the project's phase-gate philosophy.

## What Changes

- **Advisory CI reminder:** A repo-local GitHub Actions workflow (never kit — the docs.yml and release.yml pattern) runs on pull requests, detects kit-path changes without a corresponding **Kit version file** bump, and posts an advisory annotation — for example, "kit changed — bump the kit version file so a release is cut on merge." The reminder is advisory at review time and MUST NOT block merge — including visually: its surface must not render a failing check on the pull request, since a nonzero exit shows a red X even without branch protection. It works within the DUNE organization's Actions policy — actions/checkout plus the runner's preinstalled git and gh, nothing else, the constraint release.yml already records.
- **Archive gate:** A change that touched kit files MUST NOT archive until a published **Kit release** contains those changes. The mechanism is settled: a repo-local gate script under `tools/` — Python 3.14 via uv, sibling of `tools/docs_site.py`, the **Maintainer toolchain** pattern — wired into the archive phase through `openspec/config.yaml`'s `operations.archive.guidance` hook, the established repo-local seam that already carries "Must run OpenSpec Sync before archiving." It is deliberately NOT wired into the kit-owned `.agents/skills/openspec-git-discipline/` skill: the gate is repo-local maintainer discipline, never kit-shipped behavior. A gate failure prints a pasteable fix naming the exact remedy for the diagnosed cause: the issue's text — bump the kit version file, merge, and the release cuts — for the forgotten bump, and the documented `workflow_dispatch` re-run for a misfired release run (a second bump would scope the release wrong). The gate's hardness is archive-process discipline — the archive workflow runs the gate and refuses to archive on failure — not mechanical prevention, and the spec stage words the observable rule accordingly.
- **Single-source copy-list:** The reminder, the gate, and the release workflow all read the same kit copy-list definition — a single source, no drift. Today that list is inlined in release.yml's tar command and is exactly equal to `KIT-MANIFEST.yaml`'s `paths:` block; the manifest — the kit's bill of materials, every copy-list path mapped to exactly one ownership class — becomes the single source, and release.yml's inlined list is replaced by a derivation from it, leaving bundle contents byte-identical (an equivalence the design must verify: tar member ordering, directory handling, the identity files already being `paths:` entries). The lighter alternative — the mechanisms read the manifest while release.yml keeps its inline list — loses because manifest-vs-inline drift would stay invisible until a release ships wrong. The convergence is read-side: this change does not edit `KIT-MANIFEST.yaml` — any edit to kit-owned files would itself be a kit-path change carrying its own bump.
- **ADR-0010 (enforcement decision):** A new ADR records the durable decision — reminder-plus-archive-gate over reminder-only and over merge-blocking required checks, and the gate's mechanism: a repo-local script wired through the config guidance seam, never the kit-owned skill — an application of ADR-0008's routing rule and a statement of what adopters never receive. It also records that the single-source derivation touches the release mechanism ADR-0009 describes, without changing its observable contract.
- **Documentation:** The maintainer guide's release-process section (docs/maintainer.md, "Kit Releases") documents both mechanisms — the reminder's advisory, never-blocking role; the gate, its place in the archive phase, and its per-cause pasteable fixes; and the single-source copy-list the three consumers share. The divergence manifest gains a row for the reminder workflow (the release.yml pattern) and records the gate script's repo-local home; the exact placement — a new row versus amending the existing repo-local tooling row that today reads as documentation-site tooling — is a design decision.
- **No kit bump in this change:** The change touches zero kit paths — the reminder workflow and its `.github/workflows/` siblings are repo-local the way docs.yml and release.yml are because only validate.yml is bundled; `tools/` is not on the copy-list; `openspec/config.yaml` is never-touch (the manifest's own example); docs/maintainer.md and the spec, change, and ADR files are not on the copy-list — so it carries no version bump, adds no CHANGELOG entry, and cuts no release on merge. The gate's literal first run is this change's own archive, trivially green over zero kit paths — a free smoke test; its first substantive exercise is the issue's dogfood: #9 (add-metadex-bootstrap-command), the next kit-touching change, meets the reminder at review and the gate at archive, end to end.
- **Out of scope:** New release mechanics (owned by #34); promoting the reminder to a required status check (revisit only if misses recur after this lands); and enforcement inside any **Experiment repository** — both mechanisms live in hep-metadex and speak to its maintainers.

## Capabilities

### New Capabilities
- `kit-release-discipline`: Enforcement of the kit release discipline across review and archive, spanning distinct requirement areas the spec stage will make independently testable: the review-time advisory reminder (a pull request with kit-path changes and no **Kit version file** bump receives the advisory annotation; the check never blocks merge and renders no failing status); the archive-time release-containment gate (a change that touched kit files does not archive until a published **Kit release** contains those changes — the archive workflow runs the gate and refuses on failure; a failure prints the per-cause pasteable fix; a zero-kit-path change passes trivially); the single-source copy-list (the release workflow, the reminder, and the gate all read the same kit copy-list definition — the KIT-MANIFEST `paths:` block — with the release bundle byte-identical); and the maintainer-guide documentation of both mechanisms in the release-process section.

### Modified Capabilities
- None. `kit-releases`' observable behavior is unchanged — the release workflow still cuts the same bundle from the same copy-list, byte-identical; only where the list is read from moves — so the single-source requirement is stated once, inside `kit-release-discipline`, covering the release workflow, the reminder, and the gate together rather than as a delta to the release-channel capability. No other capability's observable behavior moves either: the reminder adds a new advisory check without altering merge or branching behavior, and the gate adds archive-phase discipline without changing the change lifecycle's branching or merge requirements.

## Impact

- **Repositories:** hep-metadex gains a repo-local reminder workflow under `.github/workflows/` (alongside docs.yml and release.yml), a gate script under `tools/` beside docs_site.py, one more entry in `openspec/config.yaml`'s `operations.archive.guidance`, and ADR-0010 under `adr/`; docs/maintainer.md's Kit Releases section and divergence manifest gain the documentation; release.yml changes only where the single-source derivation lands, with bundle contents byte-identical. No experiment repository changes — nothing kit-shipped moves.
- **No breaking changes:** The kit's composition and content are untouched (zero kit paths), the release channel's observable behavior is unchanged, and existing **Workflow scaffolding** installs are unaffected. The reminder never blocks merge; the gate constrains only future kit-touching changes at archive time. This change itself performs no version bump and cuts no release.
- **Tool dependency:** None new for adopters — the kit stays zero-runtime and ships nothing from this change. The gate script extends the repo-local **Maintainer toolchain** (Python 3.14 via uv); the reminder workflow stays within the DUNE organization's Actions policy: actions/checkout plus the runner's preinstalled git and gh, nothing else.
- **Process:** Tracks issue #35, whose **Intent material** is the authoritative request. Work follows an **Issue branch** `35-enforce-kit-release-discipline` cut from `main` before the first commit; conventional commits carry the `(#35)` subject suffix; the change reaches `main` only by pull-request merge, and `Closes #35` appears only in the archive-phase commit. The change performs no kit version bump and adds no changelog entry, because it touches no kit paths.
- **Downstream:** Unblocks #9 (add-metadex-bootstrap-command) — the reminder's and gate's first substantive dogfood, per the issue's progression — with #39 (add-metadex-update-command) following #9. Promoting the reminder to a required status check stays parked unless misses recur after this lands.
- **Deferred to design (not settled here):** the reminder's exact advisory surface under the organization's Actions policy, carrying the never-red constraint (for example, an always-green check plus a `gh pr comment`); the reminder's detection semantics (what counts as "a corresponding kit version bump" — any **Kit version file** diff versus a version-line change — and which paths count as kit paths); the gate's containment-check semantics — how "a published **Kit release** contains those changes" is decided, including changes spanning multiple releases (kit files touched again after an earlier in-change bump already released) and the no-prior-release edge; the gate script's CLI shape and name; how release.yml derives its bundle list from the manifest, with bundle-equivalence verification; and the divergence-manifest placement for the gate script.
